# Template File Flow: Distributing Files to All Repositories

**How to push a new file to all managed repositories using templates.**

---

## Overview

The system supports distributing template files to repositories in two ways:

1. **Bootstrap (On Creation)** — Template files added automatically when repo is created
2. **Sync (Bulk Update)** — Template files synced to existing repositories

---

## Architecture

```
.github/templates/repo-scaffold/          ← Template source
    ├── Jenkinsfile
    ├── .github/workflows/ci.yml
    ├── infra/default/main.tf
    ├── config.yml
    ├── TEMPLATE_README.md
    └── ... (other template files)

apps/scripts/
    ├── bootstrap_repo.py                 ← Called on repo creation
    └── sync_templates.py                 ← Called for bulk updates

infra/config/repositories.json            ← User configures
    └── repository.custom_files = [...]   ← Which templates to include
```

---

## Flow #1: Bootstrap (On Repository Creation)

**Timeline:** Automatic when repo is created

### Step-by-Step Flow

```
1. USER EDITS repositories.json
   └─ Adds: operation: "create"
      └─ With: custom_files: { "Jenkinsfile": "repo-scaffold" }

2. USER COMMITS to develop branch
   └─ Workflow: manage-repos-create-pr.yml triggers

3. PR CREATED (develop → main)
   └─ Workflow: manage-repos-plan-validate.yml validates

4. PR MERGED to main
   └─ Workflow: manage-repos-apply.yml executes

5. TERRAFORM APPLY
   ├─ Creates github_repository resource
   └─ Terraform runs provisioner

6. PROVISIONER CALLS bootstrap_repo.py
   ├─ Calls: python3 apps/scripts/bootstrap_repo.py {repo_name} {repo_owner}
   ├─ bootstrap_repo.py:
   │  ├─ Clones newly created repo
   │  ├─ Copies files from .github/templates/repo-scaffold/
   │  ├─ Creates .repo-meta.json (metadata)
   │  ├─ Commits: "Initialize repository with repo-scaffold template"
   │  └─ Pushes to main branch
   └─ Repo now contains template files ✓

7. GITHUB REPOSITORY POPULATED
   └─ All template files present in main branch
```

### Configuration Example

```json
{
  "repositories": {
    "my-new-service": {
      "operation": "create",
      "name": "my-new-service",
      "visibility": "private",
      "custom_files": {
        "Jenkinsfile": "repo-scaffold",
        ".github/workflows/ci.yml": "repo-scaffold",
        "infra/default/main.tf": "repo-scaffold"
      }
    }
  }
}
```

### What Gets Pushed

**Location:** `.github/templates/repo-scaffold/`

```
.github/templates/repo-scaffold/
├── Jenkinsfile
├── .github/workflows/
│   ├── ci.yml
│   └── deploy.yml
├── infra/default/
│   ├── main.tf
│   └── variables.tf
├── config.yml
├── TEMPLATE_README.md
└── .repo-meta.json (generated by bootstrap)
```

### Code Reference

**Terraform Module** (`infra/modules/repository/main.tf`):
```terraform
resource "null_resource" "bootstrap_template" {
  depends_on = [github_repository.this]

  provisioner "local-exec" {
    command = "python3 ../apps/scripts/bootstrap_repo.py ${var.name} ${var.github_owner}"
    environment = {
      GITHUB_TOKEN = var.github_token
    }
  }
}
```

**Bootstrap Script** (`apps/scripts/bootstrap_repo.py`):
- Clones repo to temp directory
- Copies files from `.github/templates/repo-scaffold/`
- Commits with message: "Initialize repository with repo-scaffold template"
- Pushes to main branch
- Creates `.repo-meta.json` metadata file

## Flow #2: Sync (Bulk Update to Existing Repos)

**Timeline:** Manual - When you need to update template files across all repos

### Step-by-Step Flow

```
1. USER MODIFIES template files
   └─ Edits: .github/templates/repo-scaffold/Jenkinsfile
      └─ Or: adds new file to template directory

2. USER COMMITS to develop branch
   └─ Push triggers: manage-repos-plan-validate.yml (watches for changes)

3. (OPTIONAL) USER TRIGGERS sync_templates.py
   └─ Manual workflow or CLI:
      └─ python3 apps/scripts/sync_templates.py

4. SYNC SCRIPT EXECUTES
   ├─ Reads: infra/config/repositories.json
   ├─ For each repository with custom_files:
   │  ├─ Clones repository to temp dir
   │  ├─ Copies updated template files
   │  ├─ Commits: "Update templates from repo-scaffold"
   │  ├─ Pushes to main branch
   │  └─ Cleans up temp dir
   └─ Process: Create PR or direct commit (configurable)

5. ALL REPOSITORIES UPDATED
   └─ All have latest template files ✓
```

### Configuration Example

```json
{
  "repositories": {
    "service-a": {
      "operation": "create",
      "name": "service-a",
      "visibility": "private",
      "custom_files": {
        "Jenkinsfile": "repo-scaffold",
        ".github/workflows/ci.yml": "repo-scaffold"
      }
    },
    "service-b": {
      "operation": "create",
      "name": "service-b",
      "visibility": "private",
      "custom_files": {
        "Jenkinsfile": "repo-scaffold",
        ".github/workflows/ci.yml": "repo-scaffold"
      }
    }
  }
}
```

### Code Reference

**Sync Script** (`apps/scripts/sync_templates.py`):
- Iterates all repositories
- For each with `custom_files` configured:
  - Clones to temp directory
  - Copies template files from `.github/templates/repo-scaffold/`
  - Commits with message: "Update templates from repo-scaffold"
  - Pushes to main branch

## Using Templates: Step-by-Step Example

### Scenario: Add Jenkinsfile to All Services

**Step 1: Create Template File**

```bash
# Create or edit template
cat > .github/templates/repo-scaffold/Jenkinsfile << 'EOF'
pipeline {
  agent any
  
  stages {
    stage('Build') {
      steps {
        echo 'Building...'
      }
    }
    stage('Test') {
      steps {
        echo 'Testing...'
      }
    }
  }
}
EOF
```

**Step 2: Configure repositories.json**

```json
{
  "repositories": {
    "api-service": {
      "operation": "create",
      "name": "api-service",
      "visibility": "private",
      "custom_files": {
        "Jenkinsfile": "repo-scaffold"
      }
    },
    "web-service": {
      "operation": "create",
      "name": "web-service",
      "visibility": "private",
      "custom_files": {
        "Jenkinsfile": "repo-scaffold"
      }
    }
  }
}
```

**Step 3: Commit to develop**

```bash
git add .github/templates/repo-scaffold/Jenkinsfile
git add infra/config/repositories.json
git commit -m "Add Jenkinsfile template to services"
git push origin develop
```

**Step 4: Workflow Execution**

1. Workflow creates PR
2. Workflow validates + plans
3. You review PR
4. You merge to main
5. Workflow applies:
   - Creates api-service repository
   - Runs bootstrap_repo.py → Copies Jenkinsfile
   - Creates web-service repository
   - Runs bootstrap_repo.py → Copies Jenkinsfile
6. Both repositories now have Jenkinsfile ✓

**Step 5: Result**

Both repositories have:
```
main branch (initial commit):
  ├── Jenkinsfile (from template)
  ├── .repo-meta.json
  └── ... (other template files)
```

## Updating Existing Repositories

### Scenario: Update Jenkinsfile Across All Services

**Step 1: Modify Template**

```bash
# Update the template file
cat >> .github/templates/repo-scaffold/Jenkinsfile << 'EOF'

  post {
    always {
      echo 'Pipeline completed'
    }
  }
EOF
```

**Step 2: Commit Template Change**

```bash
git add .github/templates/repo-scaffold/Jenkinsfile
git commit -m "Add post-build step to Jenkinsfile template"
git push origin develop
```

**Step 3: Run Sync (Option A: Manual)**

```bash
# Manual sync via CLI
python3 apps/scripts/sync_templates.py

# Or: Create GitHub Actions workflow trigger
gh workflow run sync-templates.yml
```

**Step 4: Sync Execution**

For each repository with `custom_files`:
1. Clone to temp directory
2. Copy updated Jenkinsfile
3. Commit: "Update templates from repo-scaffold"
4. Push to main
5. Clean up temp directory

**Step 5: Result**

All repositories now have updated Jenkinsfile ✓

## Best Practices

### 1. Template Directory Organization

```
.github/templates/repo-scaffold/
├── Jenkinsfile                 # CI/CD pipeline
├── .github/workflows/
│   ├── ci.yml                  # Automated testing
│   └── deploy.yml              # Deployment
├── infra/default/
│   ├── main.tf                 # Terraform boilerplate
│   └── variables.tf
├── config.yml                  # Configuration template
├── TEMPLATE_README.md          # Usage instructions
├── .gitignore
└── LICENSE
```

### 2. Template Metadata

Each bootstrapped repo includes `.repo-meta.json`:

```json
{
  "template_version": "repo-scaffold",
  "initialized_at": "2026-10-07T12:00:00",
  "bootstrap_script_version": "1.0",
  "repository_name": "my-service",
  "repository_owner": "my-org"
}
```

### 3. Naming Conventions

- Template directory: `.github/templates/repo-scaffold/`
- Template name: `repo-scaffold` (used in custom_files)
- Metadata file: `.repo-meta.json`
- Commit message: "Initialize repository with repo-scaffold template"
- Sync commit message: "Update templates from repo-scaffold"

### 4. When to Use Bootstrap vs Sync

| Scenario | Method | Trigger |
|----------|--------|---------|
| Create new repo with files | Bootstrap | On `operation: "create"` |
| Add files to existing repos | Sync | Manual or scheduled |
| Update template across all | Sync | Manual or scheduled |
| Add one new template file | Sync | Manual or scheduled |

```json

      "operation": "create",

      "custom_files": {

      }
    }
  }
}
```

### Supported Operations

- **Create:** Custom files pushed on repo creation (via bootstrap_repo.py)
- **Import:** Custom files can be synced to imported repos (via sync_templates.py)
- **Update:** Repository settings updated; templates via separate sync

## Troubleshooting

### Template Files Not Appearing

1. Check `.github/templates/repo-scaffold/` exists
2. Verify `custom_files` configured in repositories.json
3. Check workflow logs in Actions tab
4. Verify `GITHUB_TOKEN` has push access

### Sync Not Running

1. Verify sync_templates.py exists in apps/scripts/
2. Check for manual trigger or scheduled workflow
3. Review workflow logs for errors
4. Ensure repositories.json has `custom_files` entries

### File Conflicts

If repo already has file with same name:
1. Script will overwrite existing file
2. Create PR before merging (recommended)
3. Review changes before accepting
4. Or: Use different file names
